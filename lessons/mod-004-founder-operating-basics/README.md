# mod-004 — Founder Operating Basics: Decide, Allocate, Communicate, Measure

The fourth module of **Startup Foundations**. mod-001 defined *what a startup
is*. mod-002 installed the *map* — the dependency graph of every business
thing a founder deals with. mod-003 installed the *clock* — the stage axis
that tells you which nodes on the map are load-bearing this week. This
module installs the *operating loop* — how a founder actually runs the week
those nodes get worked in.

The prior three modules taught you what to look at and when. They did not
teach you how to *run*. Left there, a founder can name every node on the
graph and every stage on the ladder and still spend Monday morning
answering Slack, Tuesday reacting to a customer email, Wednesday redoing
Monday's Slack answers as a document, Thursday firefighting the same
problem for the third time this quarter, and Friday wondering where the
week went. The graph and the stage told them *what mattered*. Nothing told
them *how the week was supposed to be shaped*.

This module installs the smallest founder operating loop that scales from
one founder alone to a two-or-three-person team: **decide, allocate,
communicate, measure**, run on a weekly cadence, backed by five cheap
artifacts (a Monday plan, a Friday shipped-and-learned, a metrics
one-pager, a decision log, and a first investor update). None of them are
process for its own sake; each one exists because a specific failure mode
of founder work is being defended against.

## What you'll be able to do

By the end of the module you should be able to:

- Run the four-part operating loop — **decide, allocate, communicate,
  measure** — on a weekly cadence, and name for each part the specific
  failure mode it defends against.
- Author a founder-narrative in the **Sequoia deck / narrative shape**
  (company purpose → problem → solution → why now → market size →
  competition → product → business model → team → financials) that a
  co-founder, a first employee, a first customer, and a first investor
  can each act on.
- Ship a lightweight weekly cadence — a **Monday plan**, a **Friday
  shipped-and-learned**, and a **metrics one-pager** — designed so the
  same three artifacts survive the first hire and the first investor
  update without redesign.
- Keep a **decision log** — a running, dated record of the calls you
  made and the reason you made them — as the artifact that defends
  against "we always thought that" revisionism from your own future
  self.
- Adopt a **lightweight OKR / commit-and-review shape** sized for a 2-3
  person startup — one company objective, three key results, weekly
  check-in — and recognise the anti-patterns (goals that are activities,
  KRs that are inputs, quarterly-only rhythm).
- Ship a **first investor-update template** — one page, three sections
  (**highlights / lowlights / asks**) — and know why the discipline of
  writing the update is worth building *before* there are outside
  investors reading it.
- Name where founder-operating **depth is owned** — this module covers
  the loop; hiring / comp / management / firing depth lives in
  [`startup-operations-governance-curriculum`](https://github.com/ai-startup-curriculum/startup-operations-governance-curriculum);
  product / GTM / sales operating loops in
  [`startup-product-gtm-curriculum`](https://github.com/ai-startup-curriculum/startup-product-gtm-curriculum);
  capital-allocation frameworks and investor-update-at-scale in
  [`startup-finance-fundraising-curriculum`](https://github.com/ai-startup-curriculum/startup-finance-fundraising-curriculum).

## How to work the module

1. Read chapters 01 → 07 in order. Chapter 01 names the loop that
   chapters 02–06 each formalise one part of; chapter 07 is the
   ownership boundary and is what keeps this module from
   silently expanding into the operations, GTM, and finance pillars.
2. **Do the exercises against a real startup.** Every exercise in this
   module is designed to be worked against a startup you actually
   care about — your own, one you're advising, one you're
   considering joining. Working the exercises against a made-up
   company loses 80% of the value; the whole point of the module is
   the discipline of *shipping artifacts about a real situation*.
3. Chapter 05 (Sequoia narrative) and chapter 06 (first investor
   update) reference the primary sources in `resources.md`. Read the
   primary source before the exercise — the chapters are scaffolding
   for the primary reference, not a replacement.
4. Keep the five artifacts you ship in the exercises in one folder
   from the beginning. The lab (authored separately) will ask you to
   run one real week end-to-end using exactly these five artifacts;
   if they are already in one folder with the shapes established,
   the lab is a one-week execution rather than a scramble to build
   the artifacts from scratch.
5. When you finish this module, revisit mod-003's stage-fit
   checklist. The operating loop tells you *how* to run a week; the
   stage-fit checklist tells you *what belongs in* the week. The two
   are complementary — the loop without the checklist runs on
   whatever landed in your inbox; the checklist without the loop
   never gets executed on.

See [`resources.md`](resources.md) for the primary references (the

Management`, John Doerr's `Measure What Matters` on OKRs, Y
Combinator's founder-update writing, and the ownership-map to the
operations, GTM, and finance pillar curricula) and the citation form
used across Foundations.
