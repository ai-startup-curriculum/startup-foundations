# mod-003 — Stages and What Matters When: The Stage Axis of the Model

The third module of **Startup Foundations**. mod-001 defined *what a startup is*.
mod-002 installed the *map* — the dependency graph of every business thing a
founder deals with. This module installs the *clock*: the stage axis that tells
you, at any moment, which nodes on the map you should actually be working, which
are premature, and which have already been delegated.

The graph tells you where a thing lives. The stage tells you whether it matters
yet. Without the stage, the graph reads as a menu of topics and a founder does
what feels sophisticated instead of what is actually load-bearing this week.
With the stage, the same graph becomes an ordered work list: *ignore this whole
branch for now; that node is your entire job; this document you thought you
needed is two stages away.*

This module is the smallest treatment that lets you look at any candidate
activity — a hire, a document, a tool purchase, a marketing spend, an investor
conversation — and decide whether it is stage-appropriate, and defend the answer
against a checklist.

## What you'll be able to do

By the end of the module you should be able to:

- Read the stage ladder — **IDEA → PRE-SEED → SEED → SERIES-A → GROWTH →
  MATURE** — and, for each stage, state the **signal you're in it**, the
  **founder's core question**, and the **typical focus**.
- Diagnose stage-mismatched activity — a seed-stage founder building a
  compensation-committee charter, a pre-seed founder studying multinational
  transfer pricing, an idea-stage founder optimising ad spend — and name the
  correct current focus instead.
- Read Paul Graham's `Do Things That Don't Scale` (July 2013) as the canonical
  IDEA / PRE-SEED reconciliation: the founder does the un-scalable hand-work
  now so the scalable machine is defensible later.
- Read the Startup Genome premature-scaling framing as the empirical anchor for
  what actually happens to companies that skip stages, and name the
  consistency dimensions on which premature scaling is measured.
- Given any candidate activity, apply the stage-fit checklist to decide whether
  it is stage-appropriate, defend the answer, and name the correct current
  focus if it is not.
- Use the `stage:` tag on every module in the org as the way the curriculum
  tells a learner *you are pre-seed — do these, ignore those* — and know how
  the front-matter contract in `STARTUP_STAGES.md` makes that legible.

## How to work the module

1. Read chapters 01 → 07 in order. The ladder in chapter 02 is used by every
   later chapter; the mismatch taxonomy in chapter 03 is what the checklist in
   chapter 06 formalises; chapter 07 assumes you already know what you're
   filtering against.
2. Read the two primary sources for chapters 04 and 05 — Graham's essay and
   the Startup Genome report — *before* you do the paired exercises. The
   chapters are scaffolding, not a substitute.
3. Do the exercises in order. Exercise 01 is a quick self-locate; exercises 02
   and 05 are where the stage vocabulary earns its keep and where a real
   candidate activity gets tested.
4. Keep a running notes file. The stage-fit checklist from chapter 06 and
   exercise 05 is the artifact you will reuse every week in mod-004
   (`Founder Operating Basics`) when you decide what actually belongs in
   next week's plan.
5. When you finish this module, revisit the module tags across the org repos
   with chapter 07 open. The `stage:` field in each module's front-matter is
   the operational output of everything you just learned.

See [`resources.md`](resources.md) for the primary references (Graham's `Do
Things That Don't Scale`, the Startup Genome premature-scaling report, Blank's
Customer Development stage framing, and the org-level `STARTUP_STAGES.md`
contract) and the citation form used across Foundations.
