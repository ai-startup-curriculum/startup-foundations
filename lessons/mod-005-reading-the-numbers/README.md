# mod-005 — Reading the Numbers: Runway, Burn, Growth, and the Composite Founder View

The fifth and final lecture module of **Startup Foundations**. mod-001
defined *what a startup is*. mod-002 installed the *map* — the
dependency graph. mod-003 installed the *clock* — the stage axis.
mod-004 installed the *operating loop* — decide, allocate, communicate,
measure. This module installs the *founder-numbers* — the small,
non-negotiable set of numbers a founder has to be able to read weekly
without a calculator.

The prior four modules taught the founder to run a deliberate week
and to make dated calls with reasons. They did not teach the founder
how much *time* those calls are being made against. A founder without
the numbers can run a beautiful weekly cadence and still be surprised
by insolvency in October. A founder with the numbers reads runway as
a number, reads growth as a rate, reads the composite as a call
(*default alive* or *default dead*), and makes the calls that
mod-004's decision log records against a live picture of how much
runway the week just spent.

This module teaches the smallest set of founder-numbers that lets a
PRE-SEED or SEED founder do that: **cash on hand, monthly burn (gross,
net, and net-after-revenue), growth rate (WoW or MoM), months of
runway, the default-alive / default-dead call, and one North-Star
metric**. It builds each one from primitives — a spreadsheet cell, a
subtraction, a division — and then interlocks them into a
**founder-numbers one-pager** that a co-founder, a first employee, or
a candidate investor can read in 90 seconds.

The module is deliberately narrow. The four terms every unit-economics
conversation depends on (**CAC, LTV, payback, gross margin**) are
introduced at the vocabulary level only — enough that a Foundations
graduate can walk into the
[`startup-finance-fundraising-curriculum`](https://github.com/ai-startup-curriculum/startup-finance-fundraising-curriculum)
unit-economics module without a glossary and know which module owns
the depth. Full financial modelling, sensitivity analysis,
capital-allocation frameworks, and fundraising financial packages are
pillar depth and are named as such in chapter 08.

## What you'll be able to do

By the end of the module you should be able to:

- Build a **working runway model** in a spreadsheet from a starting
  cash balance, a monthly burn (net cash out — hires, tools, hosting,
  rent, contractors), and a forward hiring / spend plan, and read the
  runway as a *number of months*, not a vibe.
- Distinguish **gross burn**, **net burn**, and **net burn after
  variable revenue** — and name the specific way founders lie to
  themselves about which one they are watching.
- Read growth as a **rate** — week-over-week for early-stage,
  month-over-month for post-PMF — and calibrate against the Paul
  Graham 5–7% WoW yardstick for a startup at the seed stage.
- Apply Paul Graham's **Default Alive or Default Dead** composite
  — given current runway, current growth rate, current profit
  margin, and current hiring plan, does the startup reach
  profitability before the money runs out?
- Name the four unit-economic terms — **CAC, LTV, payback, gross
  margin** — at the vocabulary level, and know which pillar module
  owns each term's depth.
- Pick a **North-Star metric** for a chosen startup — the one number
  that best captures the value the product delivers — and defend the
  choice against three alternatives.
- Ship a **founder-numbers one-pager** — this week's cash, this
  week's burn, this week's growth, months of runway, the
  default-alive / default-dead call, and one North-Star metric — that
  a co-founder or an investor can read in 90 seconds.
- Name where founder-numbers **depth is owned** — this module
  covers the founder-numbers slice; deep financial modelling,
  sensitivity analysis, capital-allocation frameworks, and full
  fundraising financial packages live in
  [`startup-finance-fundraising-curriculum`](https://github.com/ai-startup-curriculum/startup-finance-fundraising-curriculum).

## How to work the module

1. Read chapters 01 → 08 in order. Chapters 01–02 install the
   *cash-side* view (runway and burn). Chapter 03 installs the
   *growth-side* view. Chapter 04 fuses them into the
   default-alive / default-dead composite — the module's single most
   consequential call. Chapters 05–07 add the four vocabulary terms,
   the North-Star, and the one-pager that binds all of the above into
   one artifact. Chapter 08 is the boundary.
2. **Open a spreadsheet before chapter 01 and keep it open for the
   whole module.** Every chapter refers back to the same working
   model. If the model is not open, the chapters read as concepts;
   if it is open, they read as instructions.
3. **Work all seven exercises against the same startup you used for
   mod-004.** The whole point of both modules is that the artifacts
   accumulate against one real (or realistic) company; running mod-005
   against a fresh made-up company loses the cadence integration.
4. Chapter 04 (Default Alive / Default Dead) and chapter 06 (North-Star)
   reference primary sources in [`resources.md`](resources.md). Read
   the primary source before the exercise — the chapters are
   scaffolding for the primary reference, not a replacement.
5. Ship the **founder-numbers one-pager (chapter 07 / exercise 07)
   into the same folder as the mod-004 cadence artifacts**. It is the
   third section of the mod-004 metrics one-pager; the interlock is
   deliberate. When you finish this module, the mod-004 weekly
   cadence starts running against real numbers instead of placeholder
   rows.

See [`resources.md`](resources.md) for the primary references (Paul
Graham's `Startup = Growth` and `Default Alive or Default Dead`, the
Amplitude / Sean Ellis writing on North-Star metrics, the David Skok
SaaS-metrics writing on CAC / LTV / payback, and the ownership map to
the finance-fundraising pillar) and the citation form used across
Foundations.
