# mod-002 — The Dependency Graph: Placing Any Business Thing on the Map

The second module of **Startup Foundations**. mod-001 defined *what a startup is*.
This module installs the *map*: the dependency graph that every question, every
artifact, and every decision a founder deals with lives on.

Every functional pillar in the org — customer discovery, PMF, GTM, sales, growth,
incorporation, equity, governance, fundraising, financial modeling, runway, unit
economics, capital allocation, exit — is a **node** on this graph. Every node
depends on the nodes upstream of it and feeds the nodes downstream of it. The
whole point of Foundations is to teach the *positions* and the *edges*, so that
by the time you reach a pillar curriculum you already know where you are and
what the node in front of you depends on.

This module is the smallest treatment that lets you place any real business
thing — a SAFE, an interview note, a runway model, a term sheet, an ICP, a CAC
table, a board pack — on the correct node and defend the placement.

## What you'll be able to do

By the end of the module you should be able to:

- Walk the **customer-facing branch** — Customer Discovery → Product-Market Fit
  → GTM Strategy → Sales → Growth → Exit — and state what each node produces
  for the next.
- Walk the **corporate-structure branch** — Incorporation → Equity → Governance
  → Fundraising → Exit — and explain why the equity structure and the
  governance structure gate every future round.
- Walk the **economics branch** — Startup Economics → Financial Modeling /
  Runway / Unit Economics / Capital Allocation — and name which numbers are
  load-bearing at which stage.
- Place any real business artifact on the correct graph node, name its
  upstream dependencies, and name what it feeds downstream.
- Use the **Lean Canvas** and the **Business Model Canvas** as two working
  shapes for "this is the assumption set under my startup," and know when
  each is the better instrument.
- Recognise the **ownership rule** in action: every deep node has an owning
  pillar curriculum (`startup-product-gtm-curriculum`,
  `startup-finance-fundraising-curriculum`,
  `startup-operations-governance-curriculum`, `startup-exit-curriculum`), and
  Foundations only teaches the *positions* and the *dependencies*, not the
  depth.

## How to work the module

1. Read chapters 01 → 07 in order. The graph is cumulative — chapter 04 assumes
   you have chapters 02 and 03 loaded, chapter 05 assumes all three branch
   chapters, and chapter 07 assumes you have already tried to place artifacts.
2. Keep [`FUNCTIONAL_CURRICULA.md`](../../FUNCTIONAL_CURRICULA.md) open in a
   second tab. That file is the authoritative pillar map; this module teaches
   you to *read* it.
3. Do the three branch-tour exercises (01 / 02 / 03) as you finish the
   corresponding chapter. Do the artifact-placement, canvas, and lookup
   exercises after the whole map is in place.
4. When a chapter names a node whose depth lives in another repo, do **not**
   go read that repo yet. Note the placement and move on. The whole point of
   Foundations is to know *where* things live so you can visit them when they
   become stage-appropriate (mod-003 makes that call sharper).
