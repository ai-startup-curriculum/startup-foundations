# mod-001 — How Startups Work: A Startup as a System

The first module of **Startup Foundations**. Before any of the pillar work — customer
discovery, cap tables, runway, fundraising, GTM — you need a precise definition of
the thing you're working on, and a mental model of what it's trying to do and what
kills it. That's what this module installs.

Most founder education treats "startup" as a vibe. Here we treat it as a system with
a specific shape, a specific job, a specific set of failure modes, and a specific
place in a broader taxonomy. Every downstream module in the org depends on the
definition and framing you build here.

## What you'll be able to do

By the end of the module you should be able to:

- State a precise definition of a startup and explain why a small business, a
  consulting project, a lifestyle business, and a research program each fall
  outside it.
- Read the canonical Paul Graham essays (`Startup = Growth`, `How to Start a
  Startup`, `The 18 Mistakes That Kill Startups`) as reference documents about what
  a startup is trying to do and what kills it — not as inspirational reading.
- Name the two operating traditions this curriculum sits on top of — Steve Blank's
  **Customer Development** and Eric Ries's **Lean Startup / Build-Measure-Learn** —
  and explain what each one adds.
- Frame the founder's job as a **search** — for problem, solution, market,
  business model, and team — and know that each startup stage is a different
  search.
- Read three canonical startup failure post-mortems and identify which layer of
  the dependency graph (problem, solution, market, business model, GTM, capital
  structure, team) the startup actually failed on.
- Position `startup-foundations` on the level ladder of the org and know what it
  owns versus what it defers up to a functional pillar or sideways to a role
  pathway.

## How to work the module

1. Read chapters 01 → 07 in order. Skimming is fine on the second pass, not the
   first.
2. Do the exercises in order — each one grounds the chapter that preceded it.
3. When a chapter cites a primary source (a Paul Graham essay, a Blank book, a
   Founder Collective mortema, a CB Insights report), **read the primary source**.
   The chapters are scaffolding, not a substitute.
4. Keep a running notes file. You'll reuse the definitions, contrasts, and
   graph-layer mappings in every later module of Foundations and in every
   downstream pillar.
